Hyprland setup

Nebula is only the shell. It does not ship, generate or edit a Hyprland config, so the autostart and environment lines below are yours to add.

What has to be started

Three processes: the wallpaper daemon, the clipboard watcher, and the shell itself.

hyprland.conf
exec-once = awww-daemon
exec-once = wl-paste --watch cliphist store
exec-once = QSG_RENDER_LOOP=threaded quickshell

env = QML_IMPORT_PATH,$HOME/.local/lib/qt6/qml
env = NEBULA_VENV,$HOME/.local/state/quickshell/.venv

Hyprland 0.55 and later, with a Lua config

lua
hl.exec_cmd("awww-daemon")
hl.exec_cmd("wl-paste --watch cliphist store")
hl.exec_cmd("QSG_RENDER_LOOP=threaded quickshell")

hl.env("QML_IMPORT_PATH", os.getenv("HOME") .. "/.local/lib/qt6/qml")
hl.env("NEBULA_VENV",     os.getenv("HOME") .. "/.local/state/quickshell/.venv")
Why these two variables

QML_IMPORT_PATH is how Qt finds the compiled WfRecorder plugin, which the screen recorder needs. NEBULA_VENV is how the shell finds the Python interpreter that runs colour generation, weather, holidays and the file drop server. If either is unset, the features that depend on them fail quietly.

Keybinds

The shell registers named global shortcuts rather than grabbing keys itself, so you choose the keys. See Keybindings for the full list of names.

lua
hl.bind("SUPER + CTRL + RETURN", hl.dsp.global("quickshell:appLauncher"))
hl.bind("SUPER + L",             hl.dsp.global("quickshell:lock"), { locked = true })

In hyprlang syntax the same two binds are:

hyprland.conf
bind = SUPER CTRL, RETURN, global, quickshell:appLauncher
bind = SUPER, L, global, quickshell:lock

A ready-made set

A complete set of binds is committed at config/hypr/nebula.conf. Source it from your own config rather than copying it, so updates reach you:

hyprland.conf
source = ~/.config/quickshell/config/hypr/nebula.conf
